# 上位ハーネスの監査と改善の一覧（2026-10-29）

上位ハーネス（`node scripts/run-video-harness.mjs` から始まる共通の層：ハーネスの宣言・Channel Pack・品質の関門と品質ループ・
RunReceipt・Stop フック・学習（harness-learn）・並列実行）を、外部の設計資料から自分の言葉でまとめた原則に照らして監査し、
足りない所・おかしい所・一度も回っていない経路を重い順に並べた。この PR で直した物と、次に回す物を分けて書く。

- 監査のしかた：子エージェント3本（評価と品質ループ／学習・記憶・スキルの保守／Job・Receipt・実走の記録）が別々に読み、
  こちらで主な指摘をコードで確かめた（確かめた物には「確認済み」と書く）。ジャンル別の制作の仕組み3つ（このリポジトリの外）は
  読むだけで調べた。
- 原則の出どころ：有料の会員記事（全文をブラウザーで取得したもの）を読み、自分の言葉にした。原文・字幕・配布コードはこの
  リポジトリに入れていない。記事と原則の対応表は、リポジトリの外の私有ノートに置く。
- 顧客・チャンネルの名前は書かない（公開リポジトリ）。ジャンルの名前で書く。

## 1. 照らした原則（自分の言葉）

| # | 原則 | 一言で |
|---|---|---|
| P1 | 作る係と評価する係を文脈で分ける | 評価者には作る係の会話・意図・完了報告・前の回の所見を見せない。名前を変えただけでは別の評価者ではない |
| P2 | 採点の基準は作る前に固定し、緩める変更を止める | しきい値の引き下げ・項目の削減・上限の引き上げは、点が上がっても失敗。緩めるなら人が決める |
| P3 | 止める条件はコードで決める | 合格・回数・費用・時間・停滞。止まったら証拠を添えて人へ返す。止まったのに「完成」と言わせない |
| P4 | 基準の外から目的を確かめる | 基準を知らない読み手と、依頼の目的を導き直して使ってみる役。内側の点だけでは目的とのずれが見えない |
| P5 | 完了の自己申告は証拠にならない | 完了は成果物のハッシュ・デコード・試験など、外から見える AND 条件で決める |
| P6 | 人の判断と AI の予測を比べる | 人に選ばせる前に AI の予測を封印し、ずれを基準の直し案にする。直し案は人が採る |
| P7 | 同じ失敗は仕組みへ上げる | 口頭 → 注意書き → 検査 → 関門。上げたら古い注意書きは消す。上げた事実はファイルや関門の実在で確かめる |
| P8 | 記憶は「いつ入れるか」で置き場所を分ける | 常に読む物は地図だけ。操作の直前に関係する文書の場所を差し込む。残すのは判断・実測・事情・失敗。記録は追記だけ |
| P9 | スキルの境界と保守を機械で守る | 呼ぶ条件・入出力・依存・完了条件。参照切れ・使用回数を機械で見る。直した前後を同じ物で測る |
| P10 | 子エージェントへの頼み方を型にする | 目的・対象・成功条件・範囲・禁止・返す形（結論・根拠・未確認）。反復の上限と終わり方を決める |
| P11 | 実走で確かめる | 模擬の応答では起動・引き継ぎ・確認待ちの失敗が見えない。本物の別プロセス・別の会話で端から端まで回す |
| P12 | 外側のループ（能動） | 止まっている仕事・人の確認待ち・失敗の傾向を見つけて、次の仕事として人へ返す。人の承認待ちは依存として表す |
| P13 | 権限は取り返しのつかなさで分ける | 読み取りは許可、手元の変更は確認、有料・不可逆・外への影響は人の承認。お願いの文でなく実行の層で止める |
| P14 | 状態の正本と目的へのつながり | 仕事は目的・受け入れ条件・成果物へのリンクを持ち、失敗は次の仕事として切り直す |

## 2. 実際に回った記録（一度も回っていない経路）

- 公式の上位経路で `completed` かつ RunReceipt が `pass` になった Job は **0件**（漫画・ナレーションの物語・削除した解説動画のどれも）。
  実際に走った Job は16件あり、どれも `awaiting-human-review` か `failed` で止まったまま、作業フォルダごと消えた。残っているのは
  学習の索引の行だけ（Receipt 本体は索引に写していないので失われた）。
- 漫画（koya-manga-video）は公式の上位経路を一度も通っていない。漫画の署名済み Channel Pack も、チャンネルの台帳への登録も無い。
- 「署名鍵が無いので上位経路が一度も回っていない」（9/2 の残作業の表）は古い。9/24 に署名鍵が作られ、9/26〜10/6 に署名済み
  Pack で解説動画とナレーションの物語の Job が回った。止まったのは鍵ではなく、人の確認と台本の品質ループの関門。
- 試験で `completed` まで通るのは、同じプロセスの中で生成を差し替えたナレーションの物語の E2E だけ。CLI を別プロセスで
  start → resume → signoff → completed まで通す試走は無い。

## 6. 外部の配布コードが入っていないかの監査

保存済みの配布 ZIP 12件（展開して読むだけ。実行していない）とこのリポジトリを、空白を詰めた30字以上の行の一致で照らした。

  という 9 月の判断のまま）。
- 12件のどれにも LICENSE のファイルは無い。記事の本文で MIT と明記されている物も、ZIP の中に全文のライセンスが無い。配る版へは入れない。
